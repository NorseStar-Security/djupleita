# Agent Note: 课程操作审查与默认安全执行

Status: proposed

[English](2026-10-15-course-action-review-and-secure-defaults.md) | 中文

## Problem

目标范围（destination scope）并不授权对获准主机执行任意操作。即使主机名属于范围内的应用，对共享边缘代理的操作仍可能影响其他客户。浏览器、终端和任意代码必须保持可用，但不能因此把它们的目标或影响视为天然安全。

Local/Protected 选项也混淆了执行位置与安全保证。选择隔离后端并不能证明范围策略已生效、判定器正常或轨迹完整。课程需要一个具备可见就绪状态和功能一致性的默认研究环境，而不是依赖隐含配置的安全标签。

## Proposal

在目标约束之外增加可扩展的操作审查，并将隔离 Linux 运行时设为课程研究的默认环境。在接纳研究工作前，必须具备已应用的项目策略、健康的执行约束和本地轨迹收集。本提案不改变运行时行为；仍须完成实现及下述验收检查。

保留[目标约束决策](../../implemented/architecture/2026-10-14-course-network-scope.zh.md)、现有[自动审查](../../implemented/feature/2026-08-28-auto-review.zh.md)及其[审批回退](../../implemented/feature/2026-09-24-auto-review-user-approval-fallback.zh.md)，分别维护各自决策。课程操作审查补充这些机制；它不替代网络隔离，也不改变通用 harness 的权限预设。本提案不完全取代任何现有决策，因此没有符合归档条件的记录。

### 插件组合与覆盖范围

定义操作审查能力，分别通过可挂载的评估器提供方、聚合策略、工具派发消费者和轨迹消费者实现。首批提供方包含确定性规则和可配置 LLM；TypeSafe JEV 提供方使用相同接口。后续插件可增加课程特定的风险维度，无须修改智能体循环或每个工具适配器。

使用现有[工具运行时](../../../../packages/core/tools/src/index.ts)的执行前流水线和单调拒绝守卫。每个可执行的智能体工具调用都必须在执行主体前进入课程审查流程：原生工具、MCP 工具、程序化工具调用（PTC）外层 `run_code`、嵌套 `tools.*` 调用、子智能体以及后台/无界面入口。无智能体执行必须携带明确可信的执行上下文，否则拒绝。确定性硬拒绝可以跳过模型审查，但仍必须生成审计决策。不得沿用自动审查对外层程序的豁免或仅限会话的启用方式。

不可变审查输入绑定工具身份、模式、完整参数、调用/父调用/会话身份、执行环境和生效策略版本。分别提供带来源的人类授权、可信项目规则及相关状态。工具描述、页面内容、工具输出和智能体声称只能作为不可信证据，不能成为授权依据。上下文缺失、载荷不受支持或输入过大而无法审查时产生 `unknown`；不得静默截断可执行载荷后批准。

一个已审查的脚本可以在没有后续工具调用的情况下产生多种影响。审查文本不能拦截每个子进程、浏览器请求、重定向、服务工作线程或远程执行器。必须在工具派发之下保留内核目标约束和网关检查。外部执行器及服务端跳转需要独立约束；启动工具通过审查，并不意味着这些行为自动安全。

### 分类与执行约束

将可扩展风险发现与最终决策分开。初始发现覆盖破坏性影响、授权缺口、共享基础设施影响及上下文不足。把鲁莽负载、过高并发、敏感数据暴露或其他课程量表作为独立维度加入。否定发现仅表示“该评估器未识别到问题”，并非操作安全的证明。

策略将发现组合为 `allow`、`deny` 或 `require_approval`。确定性的目标、操作及完整性拒绝始终优先；模型回答或人工批准均不能覆盖它们。课程策略决定其他可审查例外是否可以进入教师审批。任何批准都必须绑定精确调用参数、策略版本、短有效期及单次执行；不得变成宽泛的能力授权。

部署必须明确选择 LLM、JEV 或两者，并记录提供方/模型及量表版本。多个必需评估器必须全部满足策略；分歧或不确定性不能隐式转为允许。参数、策略或相关状态变化后不得复用授权。评估器错误、取消、格式错误回答、必需提供方不可用及缺少审计确认均阻止执行。审查请求不携带工具，也不能递归授权自身。

将远程审查器凭据及权威决策存储保留在研究进程之外的可信管理服务中。只暴露受限审查协议，不提供任意 HTTP 中继或配置修改 API。远程提交前脱敏凭据；若脱敏删除了决策必需事实，则要求合适的本地审查器或拒绝接纳。单独配置的审查服务属于运行基础设施，不是新增研究目标。

### JEV 适配器

TypeSafe 将 JEV 描述为接收状态及类型化问题并返回结构化答案的 API。其[介绍](https://docs.typesafe.ai/introduction)建议拆分判断。应分别询问破坏性影响、共享基础设施影响、缺少授权及上下文不足，而不是要求一个模型宣告操作全面安全。保留每个答案的概率；按照[置信度文档](https://docs.typesafe.ai/confidence)，仅在问题类型提供置信度时保留该值。

将这些答案映射到统一的风险发现契约；确定性的课程代码负责阈值和决策。校验响应、固定部署的模型版本，并在启用自动接纳前通过课程测试样例校准阈值。类型化输出不能防止语义错误或不安全分类。[需认证的 API](https://docs.typesafe.ai/introduction/quickstart)是外部部署依赖：本计划不证明账户访问、可用集成、性能或安全准确率。

### 工具边界之下的操作约束

扩展网关策略，在目标检查之外，对目标主机和基础设施主机均应用硬性操作限制。一致评估规范化的 authority、方法、规范化路径及协议；拒绝模糊编码和不受支持的检查，而不是依赖原始子串黑名单。目标授权不得绕过基础设施操作限制。

在初始交战规则中加入管理关闭及破坏性共享服务控制。对 `/quitquitquit` 等情况使用隔离测试服务，绝不调用真实提供商的控制端点。HTTP 方法本身不能证明安全；对于通过请求体选择操作的 API，应在支持时采用明确的操作感知规则。否则应说明检查局限，而不是宣称完全防止破坏性操作。

原始 IP/CIDR 授权可能绕过 HTTP 层检查，并授权共享虚拟主机或其他协议。需要单独的教师授权；若操作控制是必需条件，还必须具备受中介约束的协议策略。应拒绝不兼容授权，而非宣称等效保护。当一个已接纳工具能够生成大量请求时，应在网关限制请求速率及并发。这些限制应能够独立于模型分类扩展。

### 课程安全启动与 UI

课程 GUI 和 CLI 的新研究会话默认使用隔离运行时。对恢复会话、子智能体、自动化及 API 接纳施加同样要求。原生主机管理仍作为控制平面；不得静默成为研究执行的回退路径。缺少 Docker/VM 支持、网关停止、未配置范围或必需判定器不可用时，进入设置或阻塞状态，而不是执行 Local。

首次设置必须在启用研究工具前应用明确的目标范围及交战规则。区分编辑中、已保存、已应用和观测到的生效版本。将过期状态响应覆盖新保存编辑的问题纳入本项工作。分别展示隔离、当前目标策略、操作审查及收集健康状态；后端名称使用“Isolated Linux”，而不是暗示仅有“Protected”就代表就绪。运行时无法安全提供的能力，不得宣传为无限制可用。

将不受限主机执行放在由教师控制的明确高级操作之后，附清晰警告，并使用独立会话。课程部署可以完全禁用它。已有 Local 作业不会被追溯隔离；应提供转换选择，不得静默迁移凭据、终止进程或在主机恢复执行。必需课程守卫不得通过权限预设、可选插件开关或卸载后转为 Full access 来禁用。卸载或更改必需提供方时，应关闭新接纳并使待批批准失效，直至重新建立就绪状态。

### 必需轨迹

将持久本地收集及 GUI 轨迹查看器纳入课程运行时的必需组合，而不是可选导入功能。复用[收集器](../../../../course/trajectory-collector/README.zh.md)和[查看器](../../../../packages/experimental/trajectory-viewer/README.zh.md)，并将可信收集与读取 API 放在研究智能体的可写环境之外。在宣称功能一致之前，完成隔离运行时的归档导入和导航。GUI 必须展示当前研究会话及其历史，不要求用户切换到不受限研究环境。

记录每次接纳结果、评估器/量表版本、风险发现、适用策略版本、适用时的审批身份、延迟及最终派发结果。通过现有工具、会话、父级及运行时身份关联这些记录。执行调用前持久化可信接纳记录；提交失败即阻止该调用。不得收集隐藏思维链或凭据。除非确实建立了与特定工具的关联，否则共享命名空间网络事件必须如实保留共享归属。

提供有界实时轮询、分页、轨迹树，以及按运行时、会话、工具、目标、风险和决策筛选的能力。明确显示收集延迟、缺口和断连。跨重启保留重放身份，并测试重复抑制。本地收集是必需项；只要本地持久存储容量仍可用，远程导出临时失败就不应禁用研究。存储耗尽必须可见，并在丢弃必需历史前关闭接纳。

Logfire 仍是本地持久流的可选导出器，运行于研究进程之外。学生 SSO/注册仍是[遥测注册提案](2026-10-15-course-telemetry-enrollment.zh.md)拥有的独立、尚未实现的部署要求；它和 Logfire 密钥都不是查看本地轨迹的前提。

### 交付顺序

1. 完成隔离运行时的功能一致性、必需本地轨迹、保存/应用/生效状态及就绪模型。在验证默认拒绝的路由前，保留当前启动行为。
2. 实现操作审查能力、确定性规则、LLM 提供方、完整工具派发覆盖、可信决策持久化及教师例外处理。复用现有审查基础设施，但不继承其 Full-access 策略。
3. 添加可替换 JEV 提供方、提供方契约测试、课程风险评估样例集及鲁莽负载等可配置维度。在宣传 JEV 可用前，必须完成真实账户验证。
4. 实现网关操作限制和请求预算；证明直接程序/浏览器流量无法绕过受支持控制。
5. 将所有课程研究入口切换为默认隔离接纳，提供迁移说明，并通过真实 GUI 和 CLI 验证分发的 Linux 镜像。不得在只完成工具审查里程碑后宣称端到端要求已完成。

## Alternatives considered

**启用现有 Auto 预设。** 它提供了有用的审查基础设施，但采用 Full-access 执行、排除外层 PTC 程序，并具有不同的启用、策略、审计及卸载语义。不经修改，不能将它作为必需的课程约束。

**仅以 LLM 或 JEV 作为安全边界。** 两者均可能误判影响或缺少上下文。即使模型批准，目标约束和硬性操作规则仍必须具有最终权威。

**一概拒绝浏览器、代码、终端和扫描器。** 这会破坏课程研究能力，却不能解决目标或操作授权。在可执行策略内保持能力开放，并如实说明不受支持的执行方式。

**只改变选择器默认值或标签。** 这会掩盖配置缺失及功能缺口。必须先具备就绪检查、功能一致性及无静默回退，再强制启用课程默认环境。

## Acceptance criteria

- 干净课程镜像上的真实 GUI 和 CLI 会话默认使用隔离执行。范围缺失或未应用、守卫失败及必需本地存储不可用均阻止研究执行。恢复、子智能体、后台作业及 API 入口不能回退到主机执行。
- 无密钥测试样例覆盖原生调用、外层及嵌套 PTC 调用、MCP 浏览器调用、子智能体及无智能体接纳。每次尝试的可执行派发都有审查记录；拒绝、取消或失败的审查不会改变工具主体的可观测计数器。
- 获准主机的普通请求成功。即使所有模型均回答允许，范围外主机仍被拒绝。对获准主机执行禁止的管理操作时，隔离服务的操作计数器保持零，包括来自已接纳终端代码及真实浏览器的尝试。
- 测试样例覆盖方法变化、编码/模糊路径、目标与基础设施重叠、重定向、原始 IP 例外、不受支持协议及高频请求。测试区分受支持约束与明确不受支持的请求体语义及远程跳转。
- 第三方评估器插件无需修改智能体循环或单个工具即可增加鲁莽负载规则。冲突、低确定性、缺少上下文、提示注入、过期策略版本、审查器失败及尝试移除插件均不能产生未经授权的允许。
- 批准不能覆盖硬拒绝、授权不同参数、跨策略版本生效或执行两次。并发调用及取消不能在各自可信接纳记录提交前执行。
- 隔离 GUI 通过可信读取器展示工具调用、决策、网络事件及父子轨迹。重启/重放保留历史且不产生重复事件。Logfire 导出离线时保留本地可用性并在恢复后交付；收集延迟和磁盘耗尽可见且经过测试。
- 提供方契约测试使用确定性响应。单独授权的真实提供方评估应在课程样例上测量错误允许、错误拒绝、不确定性、延迟和成本，再选择阈值；不接触公共破坏性端点进行测试。

## Risks

分类是概率性的，表面普通的操作也可能产生审查器未知的有害影响。工具审查加 HTTP 操作规则并非非破坏性行为的普遍证明。任意本地进程、不透明协议、远程跳转及沙箱逃逸需要额外控制和明确局限。

逐调用审查增加延迟、成本、提供方可用性依赖及敏感上下文处理要求。严格的不确定性及审计规则可能阻塞合法工作；应通过测量测试样例调整量表，而不是弱化硬性范围规则。必需收集需要保留策略、访问控制、容量规划及课程同意。控制主机或虚拟机监控器的学生可以抑制或伪造本地证据；本设计不提供可信证明。
